# IncidentVoice — extended demonstration plan

Aim for four to five minutes if permitted by the current submission form. There is no verified requirement in this repository for starting the demo before 90 seconds or for a particular video loudness/frame rate.

| Time | Show | Evidence to capture |
|---|---|---|
| 0:00–0:30 | Problem and incident workspace | Clearly visible simulation/live mode |
| 0:30–1:30 | Voice investigation and cited evidence | Real AssemblyAI transcript, tool output, audible reply |
| 1:30–2:30 | Stage, cancel, request again, approve | No action before approval; actual result afterward |
| 2:30–3:15 | Guided runbook | Diagnostic step, staged mutation, verification or explicit failure |
| 3:15–4:00 | Recovery check and handoff | Before/after target health; remaining impact; exported evidence |
| 4:00–4:40 | Architecture and scope | Shared approval policy; limited live adapters; session-local storage |
| 4:40–5:00 | Closing and links | Verified app, repository, and submitted artifacts |

Use [the short script](DEMO_SCRIPT.md) as the spoken foundation. Timings are approximate. Keep API keys, operator tokens, and private logs out of the recording. Do not splice a simulated successful recovery into a live-infrastructure sequence.

The business hypothesis is that conversational investigation reduces tool switching. Validate it with operators; no measured cost savings, MTTR improvement, or project-specific transcription benchmark is currently established.
